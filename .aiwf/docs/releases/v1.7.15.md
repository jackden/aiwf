# AIWF v1.7.15 — Actor Identity Evidence Semantic Migration

## Version Boundary

- Release and tool version: `1.7.15`
- Workflow protocol: `1.7.10`
- New command and evidence events: `aiwf-event-v0.4`
- Dataset version: `2`
- Task metadata: `ai-workflow-v1.7` (unchanged)

## Why This Is Not a `.post` Release

This release changes runtime/evidence semantics: configured metadata no longer
stands in for the actor that executed an event. It also changes event schema and
dataset normalization. This is an evidence semantics change, not packaging or
metadata cleanup.

## Event-Level Identity

New events separate `configured_context` from `actor_identity`, whose observations
retain declared `source` and `method`. Identity status is `unknown`,
`self_reported`, `observed`, or `conflicting`. Runtime/host observations and actor
self-reports remain distinct. Conflicts are preserved without choosing a winner.
No identity confidence score, provider verification, model ranking, or model
authorization is introduced. Labels are provenance declarations, not
authenticated model identity.

Observations are supplied directly per event or via transient live shell
`AIWF_ACTOR_IDENTITY` JSON. Profiles, local metadata, and repository `.env` cannot
supply execution observations. Missing/malformed input becomes unknown; malformed
input warns without adding a workflow blocker. Reasoning effort is execution
evidence only when observed by runtime/host.

## Zero-Action Compatibility and Optional Cleanup

Existing profiles remain loadable and usable without migration. Historical
events, tasks, review/validation artifacts, finalize events, and manifests remain
unchanged. Readers continue supporting legacy event schemas.

New profiles contain `AIWF_EVENT_LOG=1` only. Optional `profile migrate [name]`
(and `metadata profile migrate [name]`) removes only census-classified deprecated
attribution keys while preserving runtime configuration. `--dry-run` is read-only;
repeating a completed migration is a no-op. Malformed, duplicate, or unknown keys
fail closed before modification.

## Dataset and Closure

Dataset version `2` adds per-event `actor_identity_evidence` to each task and
distinguishes `runtime_observed`, `host_observed`, `self_reported`,
`configured_legacy`, `unknown`, and `conflicting`. Legacy configured evidence is
unverified execution attribution, never observed identity; matching model names
do not merge evidence classes.

Identity evidence is provenance, not completion authority. Unknown, missing, or
conflicting identity does not add validation, review, authority, AC closure,
finalize-readiness, or finalize blockers. Existing review decision-authority
checks remain in force; no cross-task dependency enforcement or new phase gate
is introduced.

## Executed Validation

- Full unit suite: `656 passed in 19.90s`, including legacy profile compatibility,
  identity schema, migration, mixed-event dataset, and workflow closure regressions.
- Read-only legacy archive verification preserved all 1,091 pre-existing files,
  the global event prefix, and four pre-existing user work files. Five historical
  finalize-ready checks matched their baseline return codes and diagnostics;
  one retained its pre-existing return code `2`.
- Independent comparison with the pre-change runtime covered all 148 historical
  tasks: finalize-ready diagnostics and existing dataset fields were identical.
- Archive dataset normalization retained 1,119 per-event evidence rows across
  153 tasks. All 405 profile-attributed legacy rows remained configured and
  unverified, with no promotion to observed execution identity.
- Migration portability was tested by simulating the absence of `os.fchmod`;
  an actual Windows full-suite run was not performed.
