# AIWF v1.7.17.post4 with MCP Adapter 0.3.2

- Release and tool version: `1.7.17.post4`
- Workflow protocol: `1.7.10`
- Optional adapter: `aiwf-mcp 0.3.2`

The optional adapter connects a local MCP client to one worktree. Start in read-only mode and check the binding with `aiwf_context`. Enable read-write mode to create tasks and record workflow evidence. The included guide covers wheel installation, building from source and client setup. [MCP setup and first task (繁體中文)](../examples/mcp_setup.md)

The separate operator channel for human review and post-finalization correction has automated fixture coverage. Live acceptance by an operator using a separate OS account is pending.

Use the [upgrade guide](../upgrading.md) to run the new source package against your project. The installer retains a v1 custom records root through conversion to v2. A pending upgrade report under `.aiwf/migrations/` records the original plan. After an interruption, use the same source and migration flags to complete verification and publish that local report. Existing project data and private Evidence-linked Guidance are preserved.

Task updates check the output paths for both event logs before changing task metadata. A task discovered in the read-only legacy tree must be migrated or handled in its original configured records root before updating it. Task titles and list fields now preserve double quotes and backslashes across workflow updates.

`inspect` verifies the required files against the manifest recorded at finalize. A finalized task with changed files reports `closure_preserved: false`. When evidence is insufficient, structured inspection returns `AIWF-INSPECT-002`. Use `./aiwf check --path TASK_PATH --finalize-ready` for the detailed diagnostics.

Single-task records exports resolve bare task IDs across discoverable task directories before applying the selection. A task-local-only export calculates its dataset from the selected task logs. Both MCP protocol generations continue to use Core for these decisions. See the [previous release notes](v1.7.17.post3.md) for supported filesystems, the operator channel and the original MCP upgrade instructions.

Older tasks with literal Windows paths retain their original title and list values when read and updated. A pre-edit guard on a read-only legacy task reports that the task needs migration; optional check and doctor logging skips that task. An explicit handoff selector can select a readable legacy task. Forced exports protect the project and workflow directories and stage the replacement before switching to the completed output.
