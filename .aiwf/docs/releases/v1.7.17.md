# AIWF v1.7.17 release candidate

- Release and tool version: `1.7.17`
- Workflow protocol: `1.7.10`
- Optional adapter: `aiwf-mcp 0.2.0`
- Machine interfaces: Query Contract v1 and Mutation Contract v1
- Task metadata: `ai-workflow-v1.7`, event schema: `aiwf-event-v0.4`, dataset: `2`

The optional stdio adapter lets an agent discover tasks, check a task, preview
closure, inspect diagnostics and consult Evidence-linked Guidance. A trusted
operator can enable writes for one bound worktree. The agent can then create a
task, run its pre-edit guard, request a phase transition, record evidence,
synchronize the index and request finalization. The installed Runtime makes the
same workflow decisions for the CLI and MCP. A recorded command is text supplied
by the caller. The Host runs the actual engineering tests and edits their evidence.

Core setup and upgrade install the Runtime and schemas without requiring the MCP
SDK or changing Host settings. Stop active workflows during upgrade. Install
the adapter in its own environment, then configure the Host with an absolute
repository path, trusted interpreter and binding. Start in read-only mode.
To remove the integration, remove its Host entry and uninstall the optional
package from its environment. The public source distribution includes installation steps and Host examples in
`integrations/mcp/README.md`. Installed repositories include the [CLI reference](../cli_reference.md).

Daily readers and writers cooperate through a local filesystem lock. Writes need
a supported local filesystem. A blocked finalize can record an audit event.
Readiness and preview describe the observed inputs at query time. Finalize
checks again while it holds the writer lock. A timeout, missing response or
partial write requires inspecting the original process and the stored evidence
before any retry. An unresolved pending marker blocks further workflow writes.
Preserve the affected records for reconciliation. External editors, older
writers and multi-host filesystems require separate coordination.

A human-required task needs an accountable human decision. The general agent
cannot submit that decision or correct a finalized task through its server.
The separate operator channel requires local deployment isolation and per-action
human confirmation. Its production acceptance requires a qualified operator
test. The existing human CLI remains available. Permission denial, a mismatched
binding and a workflow blocker must be resolved at their source before any
fallback. Public release requires a separate human decision.
