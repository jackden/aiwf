# AIWF v1.7.14 — Review Decision Authority and Workflow Evidence Diagnostics

## Release Type

Workflow protocol and runtime correctness update.

## Version Boundary

- AIWF Tool Version: `1.7.14`
- Workflow Protocol Version: `1.7.9`
- Metadata Schema Version: unchanged at `ai-workflow-v1.7`
- Event Schema Version: unchanged at `aiwf-event-v0.3`

The public baseline for this convergence is AIWF Tool Version `1.7.13.post1`
with Workflow Protocol Version `1.7.8`. The existing Task 001/002 runtime
implementation is carried into this release; this release task changes its
identity and public projections only.

## Why This Is Not a `.post` Release

AIWF v1.7.14 changes workflow closure semantics. A recorded PASS review is no
longer sufficient by itself when the task requires a stronger review
authority. The recorded decision authority must satisfy the task's required
review authority before the workflow can become finalize-ready.

Because this changes finalize-readiness semantics, the workflow protocol
advances from `1.7.8` to `1.7.9`. This release is therefore a runtime/protocol
release rather than a packaging-only `.post` update.

## Review Decision Authority

AIWF now distinguishes between:

- the authority required by the task;
- the authority behind the recorded review decision; and
- the actor or tool that recorded that decision.

A task requiring Human review authority cannot become finalize-ready solely
from an AI-agent PASS decision. The recording mechanism does not itself define
decision authority. A Human decision may still be recorded through an agent or
tool as long as the workflow evidence correctly represents the decision
authority.

This strengthens declared workflow authority enforcement. It does not provide
identity authentication or cryptographic proof of the real-world reviewer.

## Workflow Evidence Diagnostics

Derived workflow diagnostics now provide stronger visibility into workflow
evidence consistency, including:

- review/fix/re-validation closure;
- validation failure and recovery;
- review freshness;
- review authority consistency;
- metadata and latest-review consistency;
- local/global event projection consistency;
- event schema compatibility;
- workflow activity age.

These diagnostics are derived views over workflow evidence. They do not
introduce new finalize policy or replace the existing deterministic
source-of-truth gates.

## Compatibility

This release preserves compatibility with supported legacy workflow evidence,
including existing `not_required` review semantics. No metadata schema
migration is required. No event schema migration is introduced by this
release. Existing workflow records remain readable under the supported
compatibility rules.

## Not Included

This release does not introduce:

- authenticated Human identity verification;
- cryptographic approval evidence;
- strict phase state-machine enforcement;
- cross-task dependency enforcement;
- a new event schema version;
- a new metadata schema version;
- derived diagnostics as finalize blockers.

In particular, `blocked_by: ["001"]` remains a metadata/dependency
declaration; it is not a runtime cross-task finalize dependency gate.

## Validation

Release consistency was checked across the canonical runtime, README,
workflow protocol, governance/CLI documentation, package review-bundle
allowlist, and current-version tests. The targeted and full AIWF test suites,
Python compilation, and `git diff --check` are required release validation.
Task 001 and Task 002 remain finalized under their Human-authority closure
semantics. No git tag or public release was created by this task.
