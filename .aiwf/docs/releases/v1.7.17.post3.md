## Upgrading from v1.7.16

Stop workflow writers and run the upgrade from the extracted **new source package**.
This uses the new installer's destination checks and lets it repair an interrupted
upgrade even if the project's own CLI cannot start. Set both paths to absolute
directories. Review the plan before running the apply command.

```sh
SOURCE=/absolute/path/to/extracted-aiwf
TARGET=/absolute/path/to/your-project
cd "$SOURCE"
./aiwf --repo-root "$TARGET" upgrade --check --source "$SOURCE"
./aiwf --repo-root "$TARGET" upgrade --dry-run --source "$SOURCE"
./aiwf --repo-root "$TARGET" upgrade --apply --source "$SOURCE"
```

After a write failure, correct the reported filesystem problem and repeat the
check and apply from the same complete source. The installer compares managed
package files with the source, including when the displayed versions already
match. It preserves project configuration, workflow records, events and private
Evidence-linked Guidance. In the target project, run
`./aiwf agents check --path AGENTS.md`. If the managed block needs updating,
run `./aiwf agents install --path AGENTS.md --yes` and check it again. Project
instructions outside that block are preserved. [Upgrade guide](../upgrading.md)

Install, upgrade and relocation writes require a platform with no-follow
directory handles, such as Linux or macOS. On native Windows you can still
inspect the install plan, run upgrade checks or dry runs, and preview a
relocation. An already-current upgrade can return a verified no-op.

## Optional MCP access

The new local stdio adapter binds one trusted worktree. Read-only mode supports
task discovery, checks, diagnostics and Guidance. Operators can enable daily
workflow writes. Install the adapter separately in a Python 3.10+ environment.
The same server supports MCP `2026-07-28` and the `2025-11-25` handshake.
Adapter 0.3.2 fixes child process cleanup when a request is cancelled. After a
lost mutation response, inspect the task and event records before retrying.
The source package includes setup instructions in `integrations/mcp/README.md`.

Core CLI workflow writes and MCP daily operations require a supported local
filesystem with POSIX locking. Native Windows has no qualified lock backend.
The CLI reference lists supported filesystems and commands that remain available
on other storage. [CLI storage requirements](../cli_reference.md#concurrent-workflow-operations-and-recovery)

Human Review and Correction through the separate operator channel require an
independent OS account and personal terminal confirmation. Acceptance by a
qualified human operator is pending. The general agent channel can record its
own agent review. [Review workflow](../agent_rules/03_review_fix_loop.md)
